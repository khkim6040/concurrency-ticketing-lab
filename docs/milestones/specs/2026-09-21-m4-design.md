# M4 설계 — 비교·공유·해설

2026-09-21. 상위 스펙: `concurrency-ticketing-lab_spec.md`. M3 설계: `2026-09-20-m3-design.md`. 결정 근거: `docs/decisions.md`.

## 목표

같은 시드로 두 실행을 나란히 비교하는 표, 시드와 파라미터를 담은 공유 링크, 전략 11종의 접이식 해설(영어 기본, 한국어 토글), README와 데모 GIF.

DoD: 링크 하나로 타인이 동일한 결과를 재현할 수 있을 것. 시드가 고정하는 것은 좌석 선택뿐이고 오버셀 수·처리량은 타이밍에 따라 실행마다 다르므로, 여기서 "동일한 결과"는 같은 판정과 같은 패턴을 뜻한다. 숫자가 아니라 실험이 재현된다.

## 범위 밖

리포트 영속화, `GET /api/runs?compare=`, `POST /api/runs/{id}/replay`, 기준 실행 고정(pin), SSE, 실시간 라인 차트, 서버 측 시드 생성 방식 변경, 링크에 언어 포함.

## 핵심 결정

### 공유 링크는 결과가 아니라 실험을 담는다

링크는 `?seatCount=&userCount=&appInstances=&raceWindowMs=&seed=&oversell=&doubleBooking=&cacheConsistency=` 여덟 개의 쿼리 키다. 키 이름은 `RunSpec` 필드명과 같다. 링크를 열면 폼이 채워지고 곧바로 실행되어 받는 사람의 서버에서 같은 실험이 돈다. 리포트를 저장하는 결과 링크(B안)는 받는 사람이 같은 서버에 접근해야 하고 테이블과 엔드포인트가 늘어나므로 택하지 않는다. `RunController`의 "영속화는 공유 링크(M4)에서" 메모는 지운다.

### 시드는 브라우저가 만든다

JS 숫자는 2^53까지만 정확해서 서버의 `Random.nextLong()` 시드를 링크에 그대로 실으면 깨진다. UI는 `seed` 입력란이 비어 있으면 실행 직전에 `Math.floor(Math.random() * 2**31)`을 채워 넣고 항상 보낸다. 서버 기본값은 curl과 `dod.sh`용으로 남긴다. 입력란은 실행 뒤에도 값을 유지하므로 다시 "Run"을 누르면 같은 시드로 재실행된다. 스펙의 "같은 시드로 재실행" 버튼은 이것으로 대신하고, "Random" 버튼은 입력란을 비운다.

### 비교는 브라우저가 직전 리포트 하나를 기억한다

서버는 이미 리포트를 메모리에 갖고 있고 브라우저도 응답으로 받으므로, `compare` API는 같은 데이터를 한 번 더 나르는 것에 지나지 않는다. JS 변수 `prev`에 직전 리포트를 두고 새 실행이 끝나면 "previous / current / diff" 세 열 표를 그린다. 페이지를 새로고침하면 `prev`는 사라진다. 기준 실행을 고정하는 기능은 필요해지면 그때 넣는다.

### 해설은 영어 기본, 한국어 토글

README와 GIF의 독자가 저장소 방문자이므로 UI 기본 언어는 영어다. 페이지 상단의 "EN / 한국어" 버튼이 `<html lang>`을 바꾸고 선택을 `localStorage`에 기억한다. 링크에는 넣지 않는다. 번역하지 않는 것: 전략 이름, 파라미터 필드명, 지표 키, 판정 단어 `PASS`/`DEGRADED`/`FAIL`, 페이지 제목, 서버 오류 메시지, 쿼리 키. 코드·API·README와 같은 단어여야 대조가 된다. 코드 주석은 지금처럼 한국어다.

## UI (`static/index.html`, `static/lib.js`)

### 파일 구조

`index.html`은 마크업·CSS·DOM 배선만 갖고, 순수 함수는 ES 모듈 `static/lib.js`로 뺀다. `<script type="module">`로 불러오므로 빌드 단계가 없고, 같은 파일을 `node --test`가 그대로 import한다.

`lib.js`가 내보내는 것:

- `toQuery(spec)` / `fromQuery(search)`: 링크 직렬화. `fromQuery`는 여덟 키 중 하나라도 없거나 값이 허용 범위(폼의 `min`/`max`, enum 이름) 밖이면 `null`을 돌려주고 UI는 기본 폼을 보인다.
- `compareRows(prev, cur)`: 표의 행 목록 `{ key, prev, cur, diff, pct }`. `prev`가 `null`이면 `prev`·`diff`·`pct`가 `null`인 행만 나온다. `pct`는 처리량 행에만 있다(`(cur − prev) / prev`).
- `changedParams(prev, cur)`: 두 `spec` 사이에 달라진 키 목록. 표 머리에서 강조한다.
- `verdictReason(report)`: 판정 이유 문자열 키와 인자. `FAIL`이면 0이 아닌 지표 이름들, `DEGRADED`면 기준선 대비 비율, `PASS`면 없음.
- `T`: 언어별 문자열 사전. JS가 만드는 텍스트(표 열 이름, 지표 이름, 판정 이유, 잔여석 줄, 버튼 상태)만 담는다.

### 번역 방식

정적 텍스트는 HTML 안에 `<span lang="en">…</span><span lang="ko">…</span>` 쌍으로 두고 CSS 두 줄이 `html[lang=en] [lang=ko]`와 `html[lang=ko] [lang=en]`을 숨긴다. 동적 텍스트는 `T[lang][key]`. 지표 이름은 번역된 이름 뒤에 키를 괄호로 붙인다. 예: "Oversold (oversoldCount)" / "정원 초과 판매 (oversoldCount)".

### 폼

- `seed` 입력란(정수, 비어 있으면 랜덤)과 "Random" 버튼.
- 파라미터마다 필드명 옆에 짧은 설명. `seatCount` "seats N", `userCount` "concurrent users M", `appInstances` "app servers", `raceWindowMs` "delay between read and write", `seed` "same seed = same seat picks".
- 문제 축 셋의 머리에 한 줄 설명. `oversell` "sells more tickets than seats", `doubleBooking` "one seat to two users", `cacheConsistency` "what the stock viewer sees after sell-out; no strategy makes it zero". 마지막 문장이 M3의 고정 해설을 흡수한다.
- 라디오 11개마다 옆에 `<details><summary>why?</summary>` 해설. 내용은 두 언어 2\~3문장, README 해석 문단을 압축한 것. 요지:
  - oversell `NONE`: 읽고 잠들고 쓰는 사이에 다른 요청이 같은 값을 읽는다. lost update.
  - `LOCAL_LOCK`: JVM 안에서만 직렬화. 앱 1대면 정확, 2대면 두 JVM이 서로 경쟁해 무너진다.
  - `CONDITIONAL_UPDATE`: `WHERE remaining > 0`이 DB 안에서 원자적으로 판정. 락 없이 정확하고 빠르다.
  - `PESSIMISTIC`: `FOR UPDATE`가 행을 잠근 채 잠든다. 정확하지만 트랜잭션마다 커넥션을 붙들어 풀 상한이 처리량 상한이 된다.
  - `OPTIMISTIC`: 버전이 바뀌었으면 다시. 정확하고 락보다 빠르지만 재시도 수만 번이 비용이다.
  - doubleBooking `NONE`: 앱이 조회로 거른다. 조회와 삽입 사이에 다른 요청이 같은 좌석을 잡는다.
  - `UNIQUE_CONSTRAINT`: 인덱스가 두 번째 삽입을 거절한다. 위의 코드가 무엇을 했든 마지막 방어선.
  - cache `NONE`: TTL 60초까지 옛값. 실행이 그보다 짧으면 끝까지 stale.
  - `TTL_SHORT`: 창이 TTL 이하로 줄지만 닫히지 않는다. 0으로 만드는 TTL은 캐시를 없앤 것.
  - `INVALIDATE_ON_WRITE`: 마지막 쓰기의 삭제 뒤에 늦게 온 재적재는 다시 지워지지 않는다. `raceWindowMs`를 올려 보라.
  - `REDIS_AS_SOT`: 두 번째 복사본이 없다. 남는 것은 전송 지연뿐이고 `oversell` 전략은 무시된다.
- `LOCAL_LOCK` + 앱 2대 강조(기존 `hot` 클래스)가 켜지면 옆에 한 줄: "a JVM lock is per instance; two instances race each other".

### 실행 뷰

- 그리드 위에 범례 네 칸(unsold / sold / double booked / over capacity).
- 잔여석 줄은 기존대로 "viewer sees N / actual N". `ok ≥ seatCount`이고 `lastView > 0`이면 뒤에 "← stale read" 꼬리표.

### 결과

- 판정 배지 아래 한 줄 `verdictReason`. 예: "FAIL: oversoldCount, doubleBookedSeats are not 0", "DEGRADED: 38% of the NONE baseline", "PASS: all three consistency metrics are 0".
- JSON `<pre>`를 비교 표로 바꾼다. 행은 파라미터 8개(`PARAMS` 순서) 뒤에 판정 1행, 정합성 5행, 성능 10행이고 열은 직전 / 이번 / 차이다. 달라진 파라미터 행은 굵게. `diff`는 `cur − prev`를 부호와 함께, 처리량은 `pct`도 함께.
- 실행이 끝나면 `history.replaceState`로 주소창을 `toQuery(report.spec)`로 바꾸고 "Copy link" 버튼을 보인다. 버튼은 `navigator.clipboard.writeText(location.href)`.
- 이번 실행에서 고른 전략 3개의 `<details>`를 `open`으로 바꾼다. 나머지는 건드리지 않는다.

### 페이지 로드

`fromQuery(location.search)`가 `null`이 아니면 폼을 채우고 `f.requestSubmit()`. 언어는 `localStorage.lang ?? 'en'`.

## 데모 GIF (`scripts/demo-gif.sh`, `scripts/demo-gif.mjs`)

Compose 스택이 떠 있어야 한다. 셸 스크립트가 임시 디렉터리에 `playwright`를 설치하고(`npx playwright install chromium`은 캐시가 있으면 아무것도 안 한다) Node 스크립트를 실행한다. Node 스크립트는:

1. `recordVideo`를 켠 Chromium(뷰포트 900×1100)으로 `BASE/?…&seed=42&oversell=NONE&doubleBooking=NONE&cacheConsistency=NONE`을 연다. 자동 실행이 끝날 때까지(`#verdict`가 `RUNNING`이 아닐 때까지) 기다린다.
2. `oversell=CONDITIONAL_UPDATE`, `doubleBooking=UNIQUE_CONSTRAINT` 라디오를 고르고 "Run"을 누른다. 시드는 유지되므로 같은 좌석 선택으로 비교 표가 나온다. 끝나면 2초 더 머문다.
3. 브라우저를 닫아 webm을 얻고, `ffmpeg`로 팔레트 GIF(`fps=10`, 폭 720)를 만들어 `docs/demo.gif`에 쓴다.

README에는 GIF와, 2단계에서 쓰인 것과 같은 조합의 공유 링크 한 줄을 넣는다.

## 검증

- `src/test/js/ui.test.mjs`를 `node --test src/test/js`로 돈다. (1) `toQuery` → `fromQuery` 왕복, (2) 키가 빠지거나 범위 밖이면 `null`, (3) `compareRows`의 `diff`·`pct`와 `prev == null` 처리, (4) `changedParams`, (5) `verdictReason` 세 판정. 의존성 없음.
- `./gradlew test`는 서버 로직이 바뀌지 않으므로 그대로 통과해야 한다.
- DoD는 GIF 스크립트가 링크를 열어 실험을 재현하는 것으로 확인한다. `scripts/dod.sh`는 바뀌지 않는다.
- README: "What works today"에 M4 문단, 상단에 GIF, 공유 링크 예시, "Running it"에 `node --test`와 `demo-gif.sh`, 구조 목록에 `lib.js`, 로드맵 체크, 문서 링크.
- `decisions.md`에 결정 행 추가: 링크는 파라미터+시드이고 영속화 없음, 비교는 브라우저 직전 1건, 시드는 UI가 31비트로 생성, 재실행 버튼 없음, 해설은 라디오 옆 영어 기본·한국어 토글, 번역하지 않는 단어, `lib.js` 분리와 `node --test`, GIF는 Playwright 녹화.
