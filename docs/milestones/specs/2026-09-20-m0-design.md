# M0 설계 — 뼈대 관통 (오버셀 NONE / CONDITIONAL_UPDATE)

2026-09-20. 상위 스펙: `concurrency-ticketing-lab_spec.md`. 결정 근거: `docs/decisions.md`.

## 목표

웹 → 앱 2대 → MySQL → 결과 집계까지 한 줄로 연결한다. N=100, M=1,000, raceWindowMs=20으로 10회 연속 실행 시 `NONE`은 매번 오버셀, `CONDITIONAL_UPDATE`는 매번 0건이어야 한다.

## 구조

Gradle 단일 모듈, Kotlin, JDK 21, Spring Boot. 이미지 1개, 프로필로 역할 분기.

## 스키마 (M0)

```sql
CREATE TABLE IF NOT EXISTS event (
    id        BIGINT PRIMARY KEY AUTO_INCREMENT,
    run_id    VARCHAR(36) NOT NULL,
    total     INT NOT NULL,
    remaining INT NOT NULL,
    version   BIGINT NOT NULL DEFAULT 0
);
```

## API

`POST /api/runs` (web)

```json
{ "seatCount": 100, "userCount": 1000, "appInstances": 2, "seed": 42,
  "raceWindowMs": 20, "strategies": { "oversell": "NONE" } }
```
→ `{ "runId": "..." }`. 검증: seatCount 1\~1000, userCount 1\~10000, appInstances 1\~2, raceWindowMs 0\~200. 동시 실행은 1건만 허용(진행 중이면 409).

`GET /api/runs/{runId}` (web) → `status: RUNNING|DONE` + 완료 시 `RunReport`.

`POST /api/reserve` (app)

```json
{ "eventId": 1, "userId": 7, "strategy": "NONE", "raceWindowMs": 20 }
```
→ `{ "result": "OK" | "SOLD_OUT" }`.

## 실행 흐름

1. web이 `event` 행 INSERT(total=remaining=N).
2. M개 가상 스레드 생성, `CountDownLatch(1)`로 출발선 정렬. i번째 요청은 `APP_URLS[i % appInstances]`로 전송. HTTP 클라이언트는 Spring `RestClient`.
3. 요청별 결과(OK/SOLD_OUT/ERROR)와 소요 시간 기록.
4. 전원 종료 후 DB에서 remaining 조회. 집계:
   - `oversoldCount = max(0, okCount - N)`
   - `ledgerMismatch = N - (okCount + remaining)`
   - `throughput = M / 전체 소요 초`, `p50/p95/p99`
   - `verdict = oversoldCount == 0 && ledgerMismatch == 0 ? PASS : FAIL`
5. 결과를 `ConcurrentHashMap<runId, RunReport>`에 저장.

## 전략 구현 (app)

```kotlin
NONE -> {
    val remaining = jdbc.sql("SELECT remaining FROM event WHERE id = ?")...
    Thread.sleep(raceWindowMs)           // 경합 창 확대
    if (remaining <= 0) SOLD_OUT
    else { jdbc.sql("UPDATE event SET remaining = ? WHERE id = ?")...; OK }
}
CONDITIONAL_UPDATE ->
    if (jdbc.sql("UPDATE event SET remaining = remaining - 1 WHERE id = ? AND remaining > 0").update() == 1) OK else SOLD_OUT
```

`NONE`은 트랜잭션 없음(autocommit). sleep 중 커넥션을 반납해야 풀 고갈이 아닌 lost update가 관측된다.

## 설정

- `spring.threads.virtual.enabled=true` (web·app 모두)
- HikariCP `maximum-pool-size=20`
- compose: `web`에 `APP_URLS=http://app-1:8080,http://app-2:8080`, `appInstances`만큼 앞에서 사용.

## 검증

- `ReportTest`: 고정된 결과 리스트로 `oversoldCount`, `ledgerMismatch`, 백분위 계산 검증.
- `scripts/dod.sh`: compose up 후 NONE 10회, CONDITIONAL_UPDATE 10회 실행하고 각 `oversoldCount` 출력. NONE 10/10 > 0, CONDITIONAL 10/10 == 0이면 통과.
